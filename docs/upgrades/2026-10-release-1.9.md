# Upgrade notes: 1.9.0

Thresholds after discounts (optional), email verification for Store API customers, server-side rendering for themes, and refunds that fail at the payment provider. No migrations. Plugin and theme contracts stay compatible.

```bash
composer update pnscripts/pn-shop-core --with-all-dependencies
php artisan pnshop:update
php artisan optimize
```

## Required actions

- **Stripe:** copy `extensions/pnshop/stripe` (1.0.3) from the [`pnscripts/pn-shop`](https://github.com/pnscripts/pn-shop) repository, and add the event `refund.updated` to the shop's webhook in the Stripe dashboard. Without it, nothing breaks: a refund that fails later is just not reported to the shop.
- **Themes with SSR:** if you run server-side rendering (`INERTIA_SSR_ENABLED=true`) with a non-default theme, rebuild it (`npm run build:theme -- <vendor/name>`; this now also writes `themes/<vendor>/<name>/ssr`) and restart the SSR server (`php artisan inertia:stop-ssr`). Without the rebuild the theme keeps rendering in the browser only, as before.

## Behaviour changes

- **Thresholds:** unchanged unless you turn on *Settings → Orders → Thresholds use the subtotal after discounts*.
- **Verification link:** it now works without being signed in (the signature and the address hash prove it came from the email). Signed in as another customer, it is refused.
- **Refund states:** *Paid* can no longer be set by hand on a refunded or partly refunded order (admin, Admin API `transitions`); only a payment provider's failed-refund report changes it back.
