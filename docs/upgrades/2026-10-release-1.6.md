# Upgrade notes: 1.6.0

Gift cards, store credit, exchanges and return labels. Plugin and theme contracts stay compatible.

```bash
composer update pnscripts/pn-shop-core --with-all-dependencies
php artisan pnshop:update
php artisan optimize && php artisan queue:restart
```

Four migrations:

- `gift_cards`, `credit_accounts` and `balance_transactions`;
- `carts.gift_card_ids` and `carts.use_store_credit`;
- `refunds.destination` (`original` for existing refunds) and `refunds.credit_reference`;
- `return_requests.exchange_order_id`, plus the return label columns.

## Required actions

- **Staff permissions:** the new permission `sales.credit.manage` is held by administrators. Give it to the roles that issue gift cards and change store credit.
- **Rebuild themes:** non-default themes must be rebuilt and republished for the gift card field in the cart and *To pay* at checkout:

  ```bash
  npm run build:theme -- <vendor/name>
  php artisan pnshop:theme publish <vendor/name>
  ```

  Older themes keep working without these features.

## Behaviour changes

- **Paid orders:** an order becomes *paid* once its payments cover the total. With one payment per order, as before 1.6, nothing changes.
- **Payment start:** the payment started at checkout is for the amount due, after gift cards and store credit.
- **Recording a payment:** *Update payment → Paid* records what is left to pay. Before, it did nothing once any payment was paid.
- **Payment method at checkout:** it is optional in the checkout rules (storefront and Store API). Checkout asks for one whenever something is left to pay.
- **Returns:** a received return can now be *Exchanged*. Returns in the API show `refunded_to`, `exchange_order` and `return_label`.

## For plugin and theme authors

- **Carriers** can implement `PnShop\Shipping\Contracts\ProvidesReturnLabels`. Existing carriers are unaffected.
- **New pipeline:** `cart.summary`, through which a plugin can add fields to the cart (pages and Store API).
- **Cart data:** `gift_cards`, `store_credit` and `amount_due`. Delivery quotes also have `balances` and `amount_due`.
- **Refunds:** `RefundService::refund()` takes an optional `destination` (`Refund::TO_ORIGINAL` or `Refund::TO_STORE_CREDIT`).
- **Payments:** a gateway plugin receives payments for the amount due, which may be less than the order total. Use `$payment->amount`, as before.
