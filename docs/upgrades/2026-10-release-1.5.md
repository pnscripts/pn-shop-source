# Upgrade notes: 1.5.0

Channels: several storefronts on one installation, each with its own domain or path, languages, currency, theme, store details, catalog subset, stock locations, and payment and shipping methods. Plugin and theme contracts stay compatible. A shop with one store keeps working unchanged.

```bash
composer update pnscripts/pn-shop-core --with-all-dependencies
php artisan pnshop:update
php artisan optimize && php artisan queue:restart
```

Two migrations:

- `channels`, with the existing store as the default channel. It answers on every address.
- `channel_id` on `orders`, `carts` and `users`, set to the default channel for existing rows.
- One cart per customer and channel: the unique index on `carts.user_id` becomes `(user_id, channel_id)`.
- Visibility tables `channel_product`, `category_channel` and `channel_page`. They start empty, so everything stays visible.

## Required actions

None for a single store. To add a storefront, see [Channels](../ecommerce/channels.md): point its domain at the server (DNS, web server, HTTPS) and create it in Admin → Store → Channels. The new permission `system.channels.manage` is held by administrators; give it to other roles that should manage channels.

## Behaviour changes

- **Requests** are matched to a channel by domain and first path segment before anything else. A path channel becomes the request's base URL, like the language prefix.
- **Amounts in other currencies:** catalog prices, shipping costs, promotion amounts and minimums, payment method limits and group minimum orders are now treated as default-currency amounts and converted when a channel sells in another currency. With one currency nothing changes.
- **Payment method limits** in another currency used to be skipped; they are now converted and applied.
- **Carts** are kept per channel. The guest cart cookie keeps its name (`pnshop_cart`) for the default channel; other channels add their code.
- **Order emails and signed order links** use the order's channel (its store name and address).
- **Sitemaps** are cached per channel.

## For plugin and theme authors

- New services:
  - `PnShop\Channel\Channels`: `current()`, `isActive()`, `using()`;
  - `PnShop\Localization\CurrencyConverter`: `convert()`, `fromDefault()`;
  - `Localization::currency()`.
- Amounts your plugin reads from its settings are in the default currency; convert them for the cart's currency. The bundled handling-fee plugin shows how.
- `catalog.price` stages may offer prices in the default currency; `PriceQuote::offer()` converts them.
- Models can use `PnShop\Channel\Concerns\LimitedToChannels`.
- `Product::active()`, `Category::active()` and `Page::live()` only return what the current storefront channel may show. In the admin and the console they return everything, as before.
- `ProductVariant::regularPrice()` is the regular price in the channel's currency. Use it instead of `$variant->price` on the storefront.
- Admin API:
  - orders have `channel` and `filter[channel]`;
  - products have `channel_ids`;
  - price lists take `currency` on create.
