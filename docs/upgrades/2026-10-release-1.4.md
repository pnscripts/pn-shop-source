# Upgrade notes: 1.4.0

Several stock locations: stock per warehouse or shop, transfers, orders reserved and shipped per location, and pickup at a location. Plugin and theme contracts stay compatible. A shop with one location behaves as before.

```bash
composer update pnscripts/pn-shop-core --with-all-dependencies
php artisan pnshop:update
php artisan optimize && php artisan queue:restart
```

Three migrations:

- `stock_locations` gets `sells_online`, `position` and an address;
- new table `order_item_allocations`;
- `shipments.stock_location_id`.

No data is rewritten: open orders from before 1.4 get their allocation at the default location the first time stock moves for them.

## Required actions

None for a shop with one location. To use several:

1. Add locations in Admin → Catalog → Stock locations, with their country if orders should be served from the nearest one.
2. Enter each product's stock per location (*Stock by location*), or move stock with *Transfer stock* or the Admin API.
3. For pickup at a shop, choose its *Stock location* in the pickup method's settings.

Rebuild non-default themes (`npm run build:theme -- <vendor/name>`, then `php artisan pnshop:theme publish <vendor/name>`) to show pickup availability at checkout. Older themes keep working without it.

## Behaviour changes

- **What the shop sells:** stock at inactive locations, or at locations with *Sells online* off, no longer counts as available online.
- **Product and variant forms:** the single *Stock on hand* field edits the default location. With several locations its label says so. Before, it compared against the total of all locations.
- **Checkout:** stock is reserved after the delivery option is checked, so a pickup order can reserve at its location.
- **Shipments:** with several locations, a parcel leaves from one location. Shipping an order whose units are held at several locations needs a location (the admin asks; the Admin API answers 422 without `location`).

## For plugin and integration authors

- `InventoryService`:
  - new: `availableAt()`, `onHandAt()`, `reservedAt()`, `transfer()`;
  - `available()` sums the online locations;
  - it is now registered per request (scoped) instead of once per process.
- New reason `StockMovementReason::Transfer`.
- `ShipmentService::ship()` takes an optional last argument, `?StockLocation $location`.
- Order stock moves go through `PnShop\Sales\StockAllocations`. Use it, or `OrderWorkflow` and `ShipmentService`, rather than calling `reserve()` and `commit()` for order lines yourself.
- Admin API:
  - `/stock-locations`;
  - `location` on variant stock and on shipments;
  - `POST /variants/{id}/stock/transfers`;
  - variants have `locations`;
  - order detail has `allocations` and `shipments[].location`.
- Store API: delivery options have `pickup` (`null` unless the method is pickup at a stock location).
